# 分析模型

- 版本：v0.2（2026-11-18，新增外部单位实体，见 ADR-0007）
- 状态：方法设计；阈值待真实数据标定
- 原则：所有数字由确定性代码计算，可复算；模型只提供抽取与措辞（ADR-0005）

## 1. 三张图

从断言构建三张图，共享同一批实体与证据。

| 图 | 节点 | 边 | 用途 |
|---|---|---|---|
| `G_work` | 人、任务 | `(p,t,role)`，role ∈ {owner, contributor, approver, backup} | 归属、单点、负载、角色重叠 |
| `G_dep` | 任务 | `u → v` 表示 **v 依赖 u**（u 是前置） | 阻塞链、支配点、级联影响 |
| `G_collab` | 人 | 同一时间窗内共同承担 ≥1 个任务；权重=共同任务数×时间衰减 | 割点、桥、孤岛、连通性 |

### 1.1 实体类型

| 实体 | 是否入人—人图 | 说明 |
|---|---|---|
| `Person` 本队成员 | 入 | 有编号（P01…），是负载、单点、割点的唯一计算对象 |
| `Task` 任务 | — | 图的中间节点 |
| `ExternalUnit` 外部单位 | **不入** | 与团队平级的部门、商家等；负责人不在群内，也不该由本队维护（ADR-0007） |

任务的承接方若在外部单位，用 `awaiting` 表达：`task --awaiting--> external_unit`，含义是「这件事卡在这个单位身上」。
`awaiting` 不占 `owner` 槽位：任务仍可有一个本队 owner 负责去催、去对接。

约定：
- 每个任务最多一个 `owner`；出现多个 owner 记为 `ROLE_CONFLICT` 风险，而不是取其一。
- `backup` 只在有证据（曾参与、明确授权、已文档化）时建立；无证据则为空。
- 快照不可变；改数据即生成新快照，保证结论可回溯。

## 2. 指标

记 `n` 为成员数，`T_crit` 为关键任务集合（绑定对外截止，或阻塞 ≥2 个后续任务）。

### 2.1 任务权重

```text
w(t) = u(t) × (1 + d(t))
u(t)：截止 <7 天 = 3，<30 天 = 2，其余 = 1（无截止 = 1）
d(t)：t 的后继任务数（传递闭包）
```

### 2.2 单点承担指数

```text
SPI(v) = Σ w(t)  [t ∈ T_crit, owner(t)=v, backup(t)=∅] / Σ w(t) [t ∈ T_crit]
```

`SPI(v) > 0` 即存在无备份的关键责任。排序后取 Top-k 呈现，不设"合格线"。

### 2.3 依赖集中度（归一化 HHI）

```text
s_i = L(i) / Σ L
HHI = Σ s_i²
HHI_norm = (HHI − 1/n) / (1 − 1/n)     n > 1
```

`HHI_norm ∈ [0,1]`；0 = 完全均分，1 = 全部压在一人。初始阈值 0.30 视为集中，**待标定**。
外部参照：Cross 等（2016）发现 3–5% 的人承担 20–35% 的增值协作，且当超过 25% 的关系方都向其索取时间时，绩效与离职风险同时恶化。

### 2.4 负载

```text
L(p) = Σ w(t)  [t 未完成, owner(t)=p]
相对负载 = L(p) / median(L)
```

只统计可观测的未完成事项，**不估计真实工时**。相对负载 >1.5 且关键任务 ≥2 时提示过载。

### 2.5 割点、桥与割点影响

在 `G_collab`（无向）上计算：
- 割点（articulation point / cut vertex）：移除后连通分量增加的节点；
- 桥（bridge）：移除后图断开的边；
- **割点影响**：`drop(v) = |LCC(G)| − |LCC(G−v)|`，即最大连通分量缩小的人数，用于排序而不是只报"是/否"。

**适用条件（必须检查）**：十人团队的"共同参与"投影往往接近完全图，割点会稀少甚至为零。计算前先报 `density`；若 `density > 0.7` 或割点为空，改用**二部流图上的支配点**：节点为「人 + 任务」，边为归属/参与，移除某人后若某任务不再连通到任何其他人，该人即为该任务的单点。此时界面上写"单点承担"，不写"割点"，避免术语误用。

注意：割点只对无向图有定义。任务依赖图是**有向图**，必须用支配点，不能套用割点。

### 2.6 支配点与阻塞链（`G_dep`）

- 加虚拟起点连向所有入度为 0 的任务，计算立即支配点（immediate dominators）。
- 若节点 `d` 支配 ≥2 个终止任务（无后继或绑定截止），则 `d` 是**真单点**：任何路径都绕不开它。
- 阻塞链长度 = 最长有向路径；下游任务数 `d(t)` 用于任务权重与风险排序。
- 检测到环即报 `DEP_CYCLE`，视为数据或逻辑错误，不参与链路计算。

### 2.7 角色重叠

对成员 `a,b`，取其任务类别分布或位置集合：
- 集合口径：`J(a,b) = |P_a ∩ P_b| / |P_a ∪ P_b|`
- 分布口径：类别向量的余弦相似度

重叠必须分三类解释，不能一律视为问题：

| 类型 | 判定 | 含义 |
|---|---|---|
| 冗余型 | 两人都能做，且有明确 backup | 正向：抗风险 |
| 冲突型 | 同一任务/位置有 ≥2 个 accountable | 负向：决策打架 |
| 真空型 | 同类任务无人 accountable | 负向：推诿 |

### 2.8 结论稳定性

对抽取置信度做 bootstrap（默认 200 次，按置信度重采样断言），记录：
- Top-5 风险集合的 Jaccard 稳定度；
- 各指标的分位区间。

稳定度低于 0.6 时，界面显示"结论不稳，建议补充记录"，而不是照常输出排名。
`n < 15` 时，指标同时给出与度序列保持的随机零模型对比的 z 分数（小网络指标对规模与密度高度敏感）。

## 3. 断档仿真与交接清单

给定拟退出成员 `v`，在快照上模拟移除：

```text
orphaned   = { t | owner(t)=v 且 backup(t)=∅ }
bridges    = { e | e 是桥且 e 与 v 相连 }
componentΔ = components(G_collab − v) − components(G_collab)
cascade    = orphaned 的后继闭包
```

按三组输出：

| 组 | 内容 | 排序 |
|---|---|---|
| 必须补位 | 关键任务且无备份 | 截止时间 + 级联规模 |
| 需要交接 | 有备份但无交接记录 | 备份证据强度 |
| 风险提示 | 割点/桥断裂、决策无记录、下游阻塞 | impact |

每条必须携带 `task_id` 或 `edge_id` 与证据；无法指向具体对象的条目不输出。

## 4. 建议 = 图上的编辑 + 重算

建议不是一段文字，而是一组可执行编辑；"预期效果"等于应用编辑后重新计算的指标差值。

| 编辑 | 语义 | 主要影响 |
|---|---|---|
| `reassign(t, a→b)` | 换责任人 | SPI、负载、HHI |
| `add_backup(t, p)` | 指定备份 | SPI、断档级联 |
| `pair(t, a, b)` | 加共同承担 | 备份、协作连接 |
| `split_role(pos, k)` | 拆位置 | HHI、冲突型重叠 |
| `document(t)` | 补文档，视为可接手 | SPI（文档化后不再算唯一持有） |
| `defer/drop(t)` | 降载或取消 | 负载、阻塞链 |

代价估计（明确标注为估计）：涉及人数、需新增的同步次数、预计工时（用户填或按任务权重折算）。
每条建议同时给出 `ΔSPI`、`ΔHHI_norm`、`Δmax_load`、`移除同一成员时 orphaned 数的变化`。

`document(t)` 把任务视为可接手，是一个**建模假设**，不是事实；界面需注明。

## 5. 风险分类

| 类型 | 触发条件 | 严重度 |
|---|---|---|
| `SPOF_TASK` | 关键任务唯一 owner 且无 backup | 高 |
| `SPOF_CONNECTOR` | 割点（或二部流图单点）且 drop ≥ 阈值 | 高 |
| `OVERLOAD` | 相对负载 >1.5 且关键任务 ≥2 | 中 |
| `ISOLATE` | 度 ≤1 且无关键任务参与 | 中 |
| `ROLE_CONFLICT` | 同一任务/位置 ≥2 accountable | 中 |
| `ROLE_VACUUM` | 同类任务持续无人 accountable | 高 |
| `DEP_CYCLE` | `G_dep` 存在环 | 高（数据错误） |
| `LONG_CHAIN` | 下游任务数 ≥5 或最长路径 ≥5 | 中 |
| `UNDOCUMENTED` | 关键决定仅存在于对话，无任何记录物 | 中 |
| `HANDOVER_RISK` | 移除某成员后出现关键任务孤立 | 高 |

严重度是排序用的，不是概率；不得表述为"发生概率 xx%"。

## 6. 不可推断项（明确不做）

能力、意愿、真实工时、绩效、情绪、组织政治、非正式影响力、离职倾向，以及**外部单位的真实负载与响应速度**（我们只能看到自己等了多少天，看不到对方在忙什么，见 ADR-0007）。
理由：现有记录不足以支撑，且这类结论会对个人产生实际后果。系统输出的是**结构状态与变更影响**，不是对人的评价。

## 7. 待标定清单

1. `HHI_norm` 阈值（当前 0.30）与 `n` 的关系。
2. `drop` 阈值；割点为空时的二部流图口径如何与割点口径统一排名。
3. 相对负载 1.5 的合理性。
4. 稳定性 0.6 的可接受线。
5. 建议代价的折算口径。
6. 中文口语抽取错误对上述指标的传导幅度（R-04 的核心问题）。
7. 十人团队下哪种投影（共同参与 / 关键任务 / 二部流图）能产生有解释力的割点或单点，需用真实数据验证（R-08）。
