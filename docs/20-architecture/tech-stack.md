# 技术选型

- 版本：v0.1（2026-11-17）
- 状态：方向已定；标"待 spike"的项需在 2026-12 前验证
- 完整取舍理由见 `.agent/10-decisions/ADR-0004-tech-stack.md`

## 1. 选型原则

1. **单机能跑**：比赛现场只保证一台笔记本与电源。
2. **少一个活动部件，少一种失败方式**：不引入消息队列、图数据库、微服务。
3. **核心算法可单测**：指标与仿真必须是纯函数，不依赖网络与模型。
4. **换模型不改口径**：模型只是抽取器，替换不应改变字段定义与指标。
5. **依赖可解释**：每个库都能在答辩时说明"为什么是它"。

## 2. 栈

| 层 | 选择 | 理由 | 放弃的方案 |
|---|---|---|---|
| 语言（前端） | TypeScript（strict） | 与后端契约自动生成类型，减少两语言漂移 | JavaScript |
| 构建 | Vite | 纯客户端应用，构建快、配置少 | Next.js（无 SSR 需求，RSC 增加演示不确定性） |
| UI | React + Tailwind + shadcn/ui | 组件可复制、可控，不锁定运行时 | Ant Design（风格重、定制成本高） |
| 图可视化 | Cytoscape.js（待 spike 对比 AntV G6） | 交互成熟，点节点/边出证据侧栏；布局扩展多 | D3 手写（工时不可控）、ECharts graph（交互弱） |
| 图表 | ECharts | 指标面板、分布与趋势；中文文档完善 | Recharts（能力较弱） |
| 数据请求 | TanStack Query | 缓存、加载态、重试开箱即用 | 手写 fetch（重复造轮子） |
| 路由 | React Router | 页面少，库模式足够 | 文件路由框架 |
| 语言（后端） | Python 3.12+（本机 3.13.11） | 抽取、评测、图算法同语言 | 全 TypeScript（图算法生态弱） |
| Web 框架 | FastAPI + Pydantic v2 | OpenAPI 即契约；校验与序列化一体 | Flask（需自己补校验）、Django（过重） |
| ORM/迁移 | SQLAlchemy 2.0 + Alembic | 成熟、类型友好、迁移可控 | SQLModel（关系处理有坑）、裸 SQL（迁移难） |
| 存储 | SQLite（WAL） | 单文件、零运维、可整库备份做演示 | PostgreSQL（运维负担）、Neo4j（单机小图不需要） |
| 图计算 | networkx | 割点、桥、支配点、连通分量、中心性齐全 | igraph（安装与环境成本）、自研（不可靠） |
| 模型 | DeepSeek（OpenAI 兼容） | 中文抽取质量/成本平衡；在赛事指定国产工具清单内 | GPT/Claude（成本与合规不确定性）、本地 7B（显存与质量未验证） |
| 模型调用 | httpx + 自写重试/限流 | 依赖少，超时与降级可控 | 官方 SDK（版本变动风险） |
| 任务执行 | FastAPI BackgroundTasks + SSE | 单用户、分钟级任务足够 | Celery + Redis（过度设计） |
| 契约 | Pydantic → OpenAPI → `openapi-typescript` | 单一事实源，前端类型自动生成 | 手写两套类型 |
| 测试 | pytest（后端）、Vitest（前端）、Playwright（E2E，后期） | 与栈匹配 | 只靠手测 |
| 质量 | ruff（lint+format）、ESLint + Prettier | 快、配置少 | flake8+black+isort 三件套 |
| 部署 | Docker 多阶段，单进程单端口 | 减少现场故障点 | Nginx+多容器、云托管 |
| Python 环境 | venv + pip + `requirements.txt` | 本机无 uv，避免新增前置条件 | uv（可后续切换） |

版本策略：不在文档里写死小版本号；脚手架时锁定到 lockfile / `requirements.txt`，升级单独提交并跑评测。

## 3. 关键实现约束

- 前端不实现任何指标；所有数字来自 API，避免两处口径。
- 上传限制：单文件 ≤5 MB，单次 ≤200 条记录；超出提示分批。
- 模型调用：单次抽取值 ≤8k tokens；长记录按时间窗切片；并发 ≤3。
- 所有模型输出先过 JSON Schema，再做证据偏移校验；偏移对不上直接判失败并重试一次。
- 日志不写原文，只写 id、长度、哈希与错误类型。
- 密钥只从 `.env` 读；`.env` 已 gitignore；仓库只提交 `.env.example`。

## 4. 性能与规模假设

| 维度 | 假设 | 依据 |
|---|---|---|
| 组织规模 | 5–15 人 | 目标用户 |
| 记录量 | 200–1000 条/组织 | 3–6 个月群聊与会议 |
| 断言量 | 5k–20k 条 | 每条记录 10–20 条断言 |
| 图规模 | ≤5k 节点 | 断言去重后 |
| 渲染 | 默认只画风险相关子图；全图按需加载 | 浏览器端可交互上限 |

超出假设时不保证体验，界面明确提示"数据量超出演示范围"。

## 6. 安全与合规

- 无多租户、无公开注册；本地单用户。若公网部署，加统一访问口令并只用脱敏数据。
- 文件上传做类型与大小校验，禁止路径穿越；解析 docx 用只读方式。
- 依赖许可证：优先 MIT/Apache-2.0；引入 GPL 类库需在文档中声明。
- 不在日志、错误信息、演示截图中出现真实姓名与原文。
