# ADR-0007：把「外部单位」建成一等实体，而不是塞进人

- 状态：提议（待队长评审）
- 日期：2026-11-18
- 决策者：张至顺（0002）／待队长 Plmt3742 确认
- 影响文件：`docs/20-architecture/analysis-model.md`、`packages/shared/extraction.schema.json`（后续）、`docs/30-research/findings/B-06-alias-resolution.md`

## 背景

B-04 的 30 条真实记录来自辩论队队内的三个群。标注人在 2026-11-18 说明了一件此前被误解的事：

> 这些群只是辩论队队内的群。聊天里出现的「办公室」「志愿站」「技术组」「自律部」「外联」「运营组」，**是与辩论队平级的其它部门**，它们的负责人**不在这些群里**。队员之所以说「我去跟办公室对接」，是因为他恰好认识那边的人，靠私人关系去协调。

数据上能验证这一点：

| 观察 | 数字 | 出处 |
|---|---|---|
| 断言没有责任人 | 35 / 83 | `B-04-owner-labels.jsonl`（责任人口径） |
| 依赖指向记录之外 | 12 / 14（86%） | `B-04-dependency-labels.jsonl` |
| 提及的正确归属是「外部单位」而非某个人 | 24 / 138（17.4%） | `B-06-mention-labels.jsonl`（人判「组织层」） |
| 提及里出现部门词 | 35 / 138（25.4%） | `B-06-mentions.jsonl` |

现状问题：`analysis-model.md` 只定义了两类节点（人、任务）。于是「我们在等办公室回复」这类事实无处安放——只能写进 `note` 自由文本，或者硬塞给某个队员（错误归属）。前者不可查询、不可统计；后者会污染负载与单点指标。

## 决策

**新增一等实体 `ExternalUnit`（外部单位），与 `Person`、`Task` 并列。**

1. `ExternalUnit` 有名字与类型（`department` / `vendor` / `other`），**没有成员、没有负载、不参与 `G_collab`、不参与人—人割点与 SPI**。
2. 任务的归属只到「本队成员」为止；若任务的承接方在外部单位，用 **`awaiting`** 关系表达：`task --awaiting--> external_unit`，含义是「这个任务卡在这个单位身上」。
3. `awaiting` 不占用 `owner` 槽位：任务仍可有一个本队 owner（负责去催、去对接），两者不互斥。
4. 指标层面的变化：
   - 负载与单点只算人，不算单位——**单位过载不在本产品的能力范围内**（我们看不到对方的负载）。
   - 「等待外部单位」的天数可统计（`awaiting_since`），作为**阻塞时长**指标，而不是负载指标。
5. 抽取层面：部门词（办公室/技术组…）不再尝试消解到人；`Actor.status` 增加取值 `external_unit`，与 `group`（本队的一个群体，如「在场的几个人」）区分开。

## 后果

**好处**

- 「我们在等谁」变成可查询的边，而不是自由文本。
- 不再出现「把办公室的活记到某个队员头上」的误归属——B-06 实测这种误指率是 64.6%。
- 与 B-12（隐私）相容：外部单位是组织信息，不涉及个人画像。

**代价**

- schema 要加枚举值与一个关系类型，属**数据模型变更**，需同步改 `extraction.schema.json` 版本号与检查器（本 ADR 只定模型，schema 改动另开单）。
- 图谱多一类孤立节点：外部单位不与人对齐，画图时要单独着色，否则视觉上像「没人负责的任务」。

**不采用替代方案的理由**

| 方案 | 否决理由 |
|---|---|
| 把部门记成 `group` 类型的 Actor | `group` 指的是本队内部的临时群体（「在场的几个人」）；把外部部门混进去，会导致「本队编制」与「外部协作方」无法区分 |
| 记成人的 `note` 自由文本 | 不可查询、不可统计，B-04 里「谁有空谁弄」已经吃过这个亏（只能塞 `note`，见 findings §8.1） |
| 为每个外部单位建一个虚拟 Person | 会污染负载、单点、割点三项指标（虚拟人会出现在 `G_collab` 里），且违反「不凭空造人」 |
| 不建模，直接丢弃这类提及 | 丢掉的是「任务卡在谁手上」这条最有用的信息，而它正是本产品要回答的问题之一 |

## 待办（本 ADR 不包含）

1. `extraction.schema.json` 增加 `Actor.status = external_unit` 与 `awaiting` 关系（需单独单子，附迁移说明）。
2. `analysis-model.md` §2 的指标公式补一句「外部单位不参与」，并在 §6「不可推断项」里加入「外部单位的真实负载」。
3. B-06 的 `roles_ambiguous` 里 6 个部门词改为映射到 `ExternalUnit`，不再产出 `D-xxx` 伪人员编号。
