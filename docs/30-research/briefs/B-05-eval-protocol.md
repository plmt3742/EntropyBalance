# 关于抽取质量的评测协议、标注规范与真值来源

- 编号：B-05（对应 R-04）
- 优先级：P0
- 预计：8 人日
- 建议角色：数据/评测
- 决策用途：决定"准确率"这三个字能不能说、怎么说；决定模型/提示词是否可上线、是否回退。
- 前置：B-04（schema v0.1）。

## 1. 要回答的问题

1. 标注单位是什么：整条记录、一句话、一个断言，还是任务/决定实例？
2. 谁标、几人标、如何裁决分歧？Cohen's κ 目标多少？哪些字段允许"可接受替代"？
3. 30 条记录够不够？如何抽样才能覆盖不同记录类型（会议/群聊/任务描述）与不同长度？
4. 指标怎么定义：任务/决定检测的 P/R/F1；责任人准确率；依赖边 F1；证据偏移正确率；下游指标稳定性。
5. 如何报告不确定性：置信区间、bootstrap、按字段分组，而不是只给一个总分？
6. 错误如何分类，才能指导下一步改提示词或改 schema？
7. 如何防止过拟合测试集？开发/测试如何划分？提示词调优能看到哪一部分？
8. 合成数据与真实数据的结果如何分开报告？哪些结论只能来自真实数据？
9. 换模型/换提示词时，如何判断"变好"而不是"换了一种错"？

## 2. 调研需求

### 2.1 必须查的资料

- AMI、ICSI、QMSum、MeetingBank、ELITR、MUG、AMC-A、OSynth、Avocado、EPA 的数据说明与评测指标。
- OSynth 报告的 assignee 准确率（约 0.69，给全上下文）——作为"归属难"的外部证据。
- AMC-A 的标注一致性（κ≈0.47）——作为"任务边界主观"的外部证据。
- ACL/NAACL 中结构化抽取的 reporting 惯例（P/R/F1、置信区间、错误分析）。

### 2.2 必须做的动作

1. 写标注规范 v1：字段定义、正反例、不确定处理、分歧裁决、证据偏移规则。
2. 双人独立标注 ≥30 条记录；计算 κ；分歧逐条裁决并记录理由。
3. 划分 dev/test（按记录划分，不按断言），test 只在阶段性评测时打开。
4. 定义并实现指标脚本：字段级 P/R/F1；owner exact + acceptable；dependency edge F1（含方向）；evidence offset accuracy；下游 Top-5 风险 Jaccard。
5. 做一次错误分析：至少 50 个错误，归入 6 类（漏抽/错归属/错依赖方向/证据偏移/过度合并/该合未合）。
6. 用 bootstrap 估计指标区间；报告样本量与区间，不只报点估计。
7. 做一次"换模型/换提示词"的对照实验，验证指标能区分差异。

### 2.3 产出物

- `data/golden/annotation-guide.md` v1。
- `data/golden/v0/*.jsonl`、`data/golden/splits.json`。
- `data/golden/eval-YYYY-MM-DD.json` 与一页评测报告。
- `docs/30-research/findings/B-05-eval-protocol.md`。
- 错误分类表与 50 个错误样例（脱敏）。

### 2.4 验收标准

- 双人 κ ≥0.6；争议字段有明确裁决规则。
- 同一模型两次运行，下游 Top-5 风险集合 Jaccard ≥0.6。
- 错误分类覆盖 ≥90% 的实际错误，剩余归入"未解释"并说明。
- 评测报告能让第三人复现：数据版本、提示词版本、模型、参数、脚本命令齐全。
- 不使用 ROUGE/BERTScore 代替结构化指标；如使用，只作为辅助。

## 3. 交互需求

### 3.1 用户要完成的动作

- 标注者：领取任务、标注、提交、查看自己的分歧。
- 裁决者：查看双人结果并排对比、选择/改写、记录理由。
- 评测者：选择数据版本与模型版本、运行评测、查看报告、对比两次结果。

### 3.2 界面必须表达的信息

- 双人标注并排 diff：一致/不一致/一方缺失，颜色区分。
- 分歧裁决页：原文、两人结果、裁决结果、理由必填。
- 报告页：字段级指标 + 置信区间 + 样本量 + 错误类型分布 + 与上次的差值。
- 版本信息：数据版本、schema 版本、提示词版本、模型名，缺一不可。

### 3.3 必须支持的交互

- 从指标下钻到具体错误样例，再回到原文。
- 两次评测对比：按字段看升/降，标出是否超出置信区间。
- 导出报告（Markdown/CSV），用于文档与答辩。
- 测试集锁定：未到阶段性评测，界面不显示 test 指标，避免调参偷看。

### 3.4 交互验收点

- 第三人能在 5 分钟内复现一次评测（按报告里的命令）。
- 能在 5 分钟内定位"这次比上次差在哪类错误"。
- 裁决记录完整，能追溯每一条最终标签的理由。

## 4. 边界与禁止

- 不删样本、不改标签来让指标好看；剔除必须记录原因与数量。
- 不把合成数据结果写成"真实组织验证"；两类结果分表报告。
- 不把一次评测当成结论；至少两次独立运行再报告稳定性。
- 不隐藏失败案例；报告必须包含错误样例。

## 5. 交付格式

按 findings 模板；额外附标注规范、splits、评测脚本说明与首份报告。
