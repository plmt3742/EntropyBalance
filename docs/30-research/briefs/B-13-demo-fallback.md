# 关于现场演示的可复现性与降级交互

- 编号：B-13（对应 R-12）
- 优先级：P1
- 预计：4 人日
- 建议角色：前端/队长
- 决策用途：决定 10 分钟答辩能否稳定完成；演示失败会否定前面所有工作。
- 前置：B-15（部署形态）。

## 1. 要回答的问题

1. 现场可能遇到的失败：断网、模型限流、机器性能不足、投影分辨率、端口占用、依赖缺失、数据损坏。哪些最常见？
2. 回放模式要保存什么：记录、断言、图、快照、指标、建议、交接清单？哪些必须预计算？
3. 启动需要多久？能否做到一条命令、60 秒内可用？
4. 在线模式失败时，如何自动降级且不露错误？降级后如何告知评委"这是演示数据"？
5. 演示脚本如何分步：导入→图谱→风险→建议→交接，每步停留多久？
6. 备用方案：录屏、截图、另一台机器、PDF 清单。触发条件是什么？
7. 现场检查清单包含什么：电源、网络、分辨率、字体、时区、浏览器版本、模型密钥？
8. 如何证明回放结果与在线结果一致，而不是"专门做的假数据"？

## 2. 调研需求

### 2.1 必须查的资料

- 往届 4C 答辩的现场要求与常见事故（学校通知、经验帖只作参考）。
- 浏览器/投影常见问题（分辨率、缩放、字体、颜色对比）。
- 离线 Web 应用的打包方式（Docker、静态托管、SQLite 随包）。

### 2.2 必须做的动作

1. 列失败模式清单，按"概率 × 影响"排序，选前 8 个设计降级。
2. 做一次断网演练：拔网线/关 Wi-Fi，从启动到完成演示，计时并记录卡点。
3. 做一次低配机器演练：限制 CPU/内存或换旧机器，记录渲染与响应。
4. 写演示脚本（分钟级），标出每步的讲解点与备用动作。
5. 录制一份完整备用视频；准备一份 PDF 版清单与截图。
6. 做一次"冷启动"测试：新机器、无缓存、只按检查清单操作。

### 2.3 产出物

- `docs/30-research/findings/B-13-demo-fallback.md`。
- 失败模式与降级矩阵。
- 演示脚本（含计时与讲解词）。
- 现场检查清单（打印版）。
- 回放包与备用录屏。
- 冷启动/断网/低配三次演练记录。

### 2.4 验收标准

- 断网环境连续 3 次演示，≥2 次完整走通。
- 冷启动 ≤60 秒；无裸报错。
- 降级后界面明确显示"回放/演示数据"，不误导。
- 非技术人员按清单能启动。
- 回放结果与在线结果在同一数据集上指标一致（差异有解释）。

## 3. 交互需求

### 3.1 用户要完成的动作

- 一键进入"演示模式"；选择数据集；开始/暂停/重置。
- 查看当前状态（在线/回放/降级）。
- 按脚本逐步操作；失败时一键切换备用。
- 结束后恢复默认状态，避免下次误用。

### 3.2 界面必须表达的信息

- 持续可见的状态徽标：在线 / 回放 / 降级。
- 当前数据集名称与时间范围。
- 降级原因（简短、不露技术堆栈）。
- 演示模式下的操作提示（下一步做什么），可关闭。

### 3.3 必须支持的交互

- 自动降级：在线失败时切换回放，不弹错误对话框。
- 一键重置：回到演示起点。
- 数据集切换：主案例 / 边界案例 / 空态。
- 键盘快捷键：下一步/上一步，避免现场找按钮。

### 3.4 交互验收点

- 切换状态不超过 1 次点击。
- 降级过程用户无感，评委只看到"演示数据"标识。
- 重置后数据与指标完全恢复。
- 演示脚本能在 9 分 30 秒内完成。

## 4. 边界与禁止

- 不隐藏"这是回放"；不把预计算说成实时计算。
- 不用真实组织数据做公网/公开演示。
- 不依赖现场网络与第三方模型；不假设有 IT 支持。
- 不为了演示效果修改指标或伪造证据。

## 5. 交付格式

按 findings 模板；额外附演示脚本、检查清单、演练记录、备用视频路径。
