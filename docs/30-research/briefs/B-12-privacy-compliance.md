# 关于小组织协作数据的隐私、同意与合规

- 编号：B-12（对应 R-11）
- 优先级：P0
- 预计：3 人日
- 建议角色：队长（可咨询导师/法务）
- 决策用途：决定数据能不能拿、能不能演示、能不能公网部署；也是答辩必问项。
- 前置：无；但阻塞 B-03 的所有访谈。

## 1. 要回答的问题

1. 会议纪要、群聊记录、任务描述分别包含哪些个人信息？谁的信息？
2. 使用这些数据需要谁的同意：群主、参与者、被提及的人？离职成员怎么办？
3. 《个人信息保护法》的最小必要、告知同意、可删除、目的限定，落到本产品具体要做什么？
4. 化名是否足够？什么情况下仍可反查到个人？映射表如何保存、谁能看、保存多久？
5. 日志、截图、演示视频、答辩材料分别有什么泄露风险？
6. 公网部署演示时，哪些数据可以上传、哪些绝对不能？
7. 学校/学院/团队内部有没有额外规定（如伦理审查、数据出境）？
8. 用户要求删除时，删除范围是什么：原文、断言、图、快照、备份、日志？
9. 未成年人或非本校成员参与时，是否需要额外同意？

## 2. 调研需求

### 2.1 必须查的资料

- 《中华人民共和国个人信息保护法》原文（重点：第 6、13、14、17、24、47 条）。
- 《数据安全法》与学校/学院的科研数据管理规定（如能找到）。
- Microsoft Viva Insights、Worklytics、Humanyze 的隐私说明（看它们如何描述"元数据、聚合、最小群体规模"）。
- 匿名化/去标识化的技术资料（k-匿名、差分隐私只需知道边界，不必实现）。

### 2.2 必须做的动作

1. 画数据流图：从原始记录到演示导出，标出每个环节的存储位置、访问者、保留时长。
2. 写一页隐私说明（给参与者看）与一份知情同意模板（含退出与删除方式）。
3. 设计化名方案：替换规则、映射表位置、删除流程、导出检查清单。
4. 做一次"删除演练"：删除映射表与原始记录后，确认断言/图/导出物无法复原到个人。
5. 做一次"泄露检查"：检查日志、错误信息、演示截图、Git 历史中是否出现真名或原文。
6. 找导师确认：是否需要伦理审查、数据集能否用于比赛提交与公开展示。

### 2.3 产出物

- `docs/30-research/findings/B-12-privacy-compliance.md`。
- 数据流图、隐私说明、知情同意模板、删除流程、导出脱敏清单。
- 泄露检查记录（含 Git 历史扫描结果）。
- 一份"答辩用隐私口径"（3 句话以内）。

### 2.4 验收标准

- 任一演示导出物不含真名、手机号、可反查的组织名。
- 删除映射后无法复原到个人（实际演练验证）。
- 日志与错误信息不含原文（抽查 ≥100 条）。
- Git 历史无真实数据（用密钥/敏感词扫描）。
- 答辩时能用 3 句话讲清：数据从哪来、怎么处理、怎么删。

## 3. 交互需求

### 3.1 用户要完成的动作

- 首次使用：阅读并确认数据使用说明。
- 导入前：预览化名结果，确认哪些名字会被替换。
- 使用中：查看"谁能看到我的数据"；随时导出或删除。
- 删除：二次确认，选择删除范围（本次导入/全部/映射表）。

### 3.2 界面必须表达的信息

- 数据存在哪里（本机/服务器）、是否会发送给第三方模型。
- 化名状态：已化名/未化名；哪些字段仍可能识别个人。
- 保留期限与删除后果。
- 演示模式与真实模式的明显区分。

### 3.3 必须支持的交互

- 一键删除：原文、断言、图、快照、映射表分别可选；删除后给出确认。
- 一键导出脱敏包：导出前强制跑检查清单。
- 关闭在线模型：切换到纯本地/回放模式。
- 访问口令（公网演示时）。

### 3.4 交互验收点

- 用户能在 30 秒内知道"数据去哪了"。
- 删除操作可完成，且有明确回执。
- 导出前必须经过脱敏检查，不能跳过。
- 演示模式有持续可见的标识，避免误用真实数据。

## 4. 边界与禁止

- 不提供法律意见；不确定的地方写"需咨询导师/法务"。
- 不把"匿名化"当万能；不承诺绝对不可识别。
- 不把真实数据上传到公网演示环境。
- 不在未同意的情况下录音、录像、摘录原文。
- 不把访谈内容用于人事判断。

## 5. 交付格式

按 findings 模板；额外附数据流图、同意模板、删除演练记录、答辩口径。
