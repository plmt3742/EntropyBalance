# 关于从中文记录中应抽取哪些事实、字段边界如何界定

- 编号：B-04（对应 R-03）
- 优先级：P0
- 预计：5 人日
- 建议角色：数据/抽取
- 决策用途：确定抽取 schema v0.1；schema 定不下来，后面的抽取、评测、指标全部无法开工。
- 前置：无；需同时读 B-05 的评测口径，避免 schema 无法评测。

## 1. 要回答的问题

1. 一条会议纪要/群聊片段里，哪些句子是决定、待办、承诺、状态更新、闲聊？边界案例有哪些？
2. "决定"与"讨论过/可以考虑"如何区分？没有明确结论词时怎么办？
3. "待办"与"承诺"的区别是什么？没有责任人的待办要不要保留？
4. 一个任务出现多个责任人、责任人缺失、责任人是"大家"时，如何表达？
5. 依赖的方向与类型：前置、资源、审批、信息；中文里分别有哪些说法？
6. 时间表达（周五前、月底、下次开会前、尽快）如何归一？无法归一时如何标注？
7. 否定、假设、转述、玩笑（"要是他能做就好了"）如何避免被抽成事实？
8. 任务层级（父任务/子任务）与跨记录合并的接口是什么？
9. schema 如何表达"不确定"与"多候选"，而不是被迫二选一？

## 2. 调研需求

### 2.1 必须查的资料

- RACI、DACI/RAPID、RAID、DSM、DMN、Jira issue link、OpenProject work package、CRediT 的字段设计。
- AMI/ICSI/QMSum/AMC-A/OSynth 的标注 schema 与论文中的字段定义。
- 中文时间表达、否定/假设/转述的语言学资料（只需够用，不做语言学综述）。

### 2.2 必须做的动作

1. 取 20 条真实记录（脱敏前先在本机处理），逐条人工标注，记录"标不下去"的位置。
2. 做一次 2 小时边界案例工作坊：把争议句分成 10 类，逐类定规则。
3. 写 JSON Schema v0.1，覆盖：人、任务、决定、承诺、依赖、证据、置信度、状态。
4. 用 10 条"必须能表达"的极端案例回归 schema：多责任人、无责任人、否定、假设、跨记录同一任务、时间模糊、依赖成环、引用他人话、玩笑、中英混用。
5. 与 B-05 对齐：每个字段都要能定义"什么算对"。

### 2.3 产出物

- `packages/shared/extraction.schema.json` v0.1（可由本单产出，后续版本另存）。
- `docs/30-research/findings/B-04-extraction-ontology.md`。
- 字段说明表：字段名、含义、取值、必填、不确定时怎么填、对应证据。
- 20 条标注样本与 10 条边界案例。
- 与 RACI/Jira/DSM 的字段映射表（用于导出与答辩）。

### 2.4 验收标准

- 3 人独立按 schema 标注同一条记录，字段级一致率 ≥0.7。
- 10 条"必须能表达"的案例全部通过，不需要临时加字段。
- 每个字段都能回答"什么算对"，可以直接用于 B-05 的评测。
- schema 中没有"其他/杂项"这类逃避字段。

## 3. 交互需求

### 3.1 用户要完成的动作

- 在标注工作台里：读原文、划证据、填字段、标"不确定"、保存、撤销。
- 对低置信度断言做确认/修改/拒绝。
- 查看 schema 变更对已有标注的影响。

### 3.2 界面必须表达的信息

- 原文与字段并排，证据高亮可见，字符偏移可核对。
- 每个字段有简短定义与一个正例/反例（悬浮或侧栏）。
- "不确定"是一等选项，不藏在二级菜单。
- 多候选（如两个可能责任人）可以并列，不强迫选一个。

### 3.3 必须支持的交互

- 键盘优先：上一条/下一条、保存、标不确定、撤销。
- 证据偏移拖动校正；偏移错误时立即提示。
- 同一记录的多条断言可折叠查看，避免长表单。
- schema 版本切换时，显示"哪些字段新增/删除/改义"。

### 3.4 交互验收点

- 标注一条中等长度记录 ≤2 分钟。
- 标注者能在不查文档的情况下说出 80% 字段的含义（靠界面提示）。
- 能标"不确定"并继续，不会卡住流程。

## 4. 边界与禁止

- 不追求覆盖所有语用现象；先覆盖能支撑分析的最小集合。
- 不把"提到"当"承诺"，不把"讨论"当"决定"。
- 不引入无法从文本验证的心理状态字段。
- 不为未来可能的需求预留大量空字段；schema 要能删。

## 5. 交付格式

按 findings 模板；额外附 schema 文件、字段表、20 条样本、10 条边界案例。
