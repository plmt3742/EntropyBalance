# 关于隐式依赖与隐性承诺的识别边界

- 编号：B-08（对应 R-07）
- 优先级：P2
- 预计：6 人日
- 建议角色：抽取/算法
- 决策用途：决定依赖图的召回上限；隐式依赖是断档的主要来源，也是与任务管理系统的差异点。
- 前置：B-04（依赖字段）、B-05（评测协议）。

## 1. 要回答的问题

1. 中文里表达依赖的线索有哪些：等、先、之后、卡在、审批、对齐、给……才能、没有他不行？
2. 隐式承诺有哪些说法："我来吧""我看看""这个我盯着""回头弄"——哪些算承诺，哪些只是客气？
3. 依赖类型如何区分：前置、资源、审批、信息、时间同步？各有什么语言线索？
4. 硬依赖与弱依赖的边界是什么？弱依赖是否应该进入图？
5. 哪些依赖是"说到但没做"，哪些是"没说到但实际存在"？后者能否从任务顺序推断？
6. 过度推断的代价是什么？精确率优先还是召回优先？
7. 如何标注"不确定的依赖"，并在界面上表达？

## 2. 调研需求

### 2.1 必须查的资料

- 协调理论（Malone & Crowston）的依赖类型：共享资源、生产者/消费者、同时性、任务/子任务。
- DSM（设计结构矩阵）中依赖的表示与强弱。
- Jira issue link / OpenProject relations 的依赖类型定义。
- 中文情态与承诺的语言学资料（只需够用）。

### 2.2 必须做的动作

1. 从 30 条记录中筛出 100 条含依赖/承诺线索的句子，人工标注：是否依赖、类型、方向、强度、证据。
2. 建立线索词典（词 + 句式 + 反例），按类型分组。
3. 设计判定提示词：要求输出依赖类型、方向、强度、证据与理由。
4. 评估：硬依赖精确率/召回率、弱依赖单独统计、方向错误率。
5. 做一次"反例测试"：礼貌语、假设句、玩笑、转述，确认不会被抽成依赖。
6. 用抽出的依赖跑一次支配点/阻塞链，观察噪声对结论的影响。

### 2.3 产出物

- `docs/30-research/findings/B-08-implicit-dependency.md`。
- 线索词典与句式表（含反例）。
- 判定提示词与评估结果（精确率优先）。
- 弱依赖展示规范（图上如何区分）。
- 对下游指标影响的初步观察。

### 2.4 验收标准

- 硬依赖精确率 ≥0.7；方向错误率 ≤10%。
- 弱依赖不与硬依赖混算，单独报告。
- 每条依赖都能回看证据；无证据的边不入图。
- 反例测试中，礼貌语/假设句误抽率 ≤10%。

## 3. 交互需求

### 3.1 用户要完成的动作

- 处理依赖确认队列："这是依赖吗？""是前置还是审批？""强还是弱？"
- 在图上查看依赖：方向、类型、强度、证据。
- 手动升级/降级依赖强度；删除错误依赖。
- 查看依赖成环提示。

### 3.2 界面必须表达的信息

- 硬依赖实线、弱依赖虚线；方向用箭头；类型用颜色或标签。
- 依赖详情：证据句、判定理由、置信度、来源记录。
- 环检测：明确提示"这组依赖形成环，可能是数据错误"。
- 影响：这条依赖被移除后，哪些任务会失去前置。

### 3.3 必须支持的交互

- 一键改强度（强/弱/删除），立即重算阻塞链。
- 从依赖跳到两个任务与证据。
- 批量确认相同句式的依赖，但保留逐条撤销。
- 过滤：只看硬依赖/只看某类型。

### 3.4 交互验收点

- 用户能区分"必须等"与"最好等"（强弱）。
- 用户能一眼看出依赖方向，不会反向理解。
- 环出现时，用户知道该改哪条边。

## 4. 边界与禁止

- 不把"提到"当"依赖"，不把礼貌语当承诺。
- 不输出无证据的边；不为了召回牺牲精确率。
- 不把弱依赖混入关键路径计算。
- 不声称能识别所有隐式依赖；明确写召回上限与失败类型。

## 5. 交付格式

按 findings 模板；额外附 100 条标注集、线索词典、提示词与评估结果。
