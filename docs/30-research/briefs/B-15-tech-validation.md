# 关于技术选型的可用性验证（图库/部署/存储/抽取）

- 编号：B-15（对应 R-14）
- 优先级：P0
- 预计：4 人日
- 建议角色：前端/后端
- 决策用途：决定 Cytoscape 还是 G6、单进程部署是否可行、SQLite 是否够用、结构化输出一次通过率；这些一旦写进代码，返工成本高。
- 前置：无。

## 1. 要回答的问题

1. Cytoscape.js 与 AntV G6，哪个更适合"点节点→侧栏→高亮邻域→筛选"的交互？样式调试成本差多少？
2. 30 节点/200 边的图，布局切换、缩放、拖拽是否流畅？1k 节点时如何降级？
3. FastAPI 托管 Vite 产物，单进程单端口是否可靠？静态路由与 `/api` 是否冲突？
4. SQLite 在 20k 断言、5k 任务下的常用查询延迟是多少？WAL 是否够用？
5. DeepSeek 结构化输出的一次通过率多少？失败主要是 schema 错、字段缺失，还是证据偏移错？
6. OpenAPI → TypeScript 类型生成是否顺畅？前端能否不手写重复类型？
7. Docker 多阶段构建能否把镜像控制在可接受大小？冷启动多久？
8. 浏览器兼容与字体/中文渲染是否有坑？

## 2. 调研需求

### 2.1 必须查的资料

- Cytoscape.js 与 AntV G6 官方文档：布局、事件、样式、性能建议。
- FastAPI StaticFiles 与 SPA fallback 的官方文档。
- SQLite WAL、索引、查询计划；SQLAlchemy 2.0 用法。
- DeepSeek/OpenAI 兼容接口的结构化输出/JSON mode 文档。

### 2.2 必须做的动作

1. S-1：用 Cytoscape 做 1 页原型，30 节点，点节点出侧栏，高亮邻域，切换 2 种布局。
2. S-2：用 G6 做同样的原型，记录工时与坑。
3. S-3：FastAPI 托管 Vite 产物，验证 `/`、`/api/health`、刷新子路由。
4. S-4：造 20k 断言/5k 任务数据，跑常用查询，记录 P50/P95。
5. S-5：用 20 条真实记录跑抽取，统计一次通过率、失败类型、修复后通过率。
6. 记录每个 spike 的实际工时与"意外问题"，这比结论更有价值。

### 2.3 产出物

- `docs/30-research/findings/B-15-tech-validation.md`。
- 5 份 spike 记录（目标/做法/结果/坑/结论）。
- 图库对比表与推荐。
- 部署验证记录（命令、镜像大小、启动时间）。
- 抽取通过率与失败类型统计。
- 对 ADR-0004 的更新建议。

### 2.4 验收标准

- 每个 spike 有明确"通过/不通过"与替代方案。
- 图库：交互无可感延迟；样式 1 天内可调到位。
- 部署：一条命令启动；刷新子路由不 404；`/api/health` 正常。
- 存储：常用查询 P95 <200 ms。
- 抽取：一次通过率 ≥80%，修复后 ≥95%。
- 结论写入 ADR 或更新 ADR-0004。

## 3. 交互需求

### 3.1 用户要完成的动作

- 在图原型上：点击节点、拖拽、缩放、切换布局、筛选、打开侧栏。
- 在部署原型上：打开页面、刷新、调用健康检查、断网后重试。
- 在抽取原型上：上传/粘贴记录、触发抽取、查看失败原因、重试。

### 3.2 界面必须表达的信息

- 加载中/失败/空数据三种状态，不能白屏。
- 图例：节点类型、边类型、风险色。
- 性能降级提示："节点过多，已只显示关键子图"。
- 抽取失败时：失败类型 + 可操作建议（重试/缩短/人工确认），不显示堆栈。

### 3.3 必须支持的交互

- 1 秒内响应点击与筛选。
- 布局切换不丢选中状态。
- 侧栏可关闭、可固定；不遮挡图。
- 抽取任务可取消、可重试；进度可见。

### 3.4 交互验收点

- 30 节点图交互无可感延迟；1k 节点有降级且不崩溃。
- 刷新任意子路由不 404。
- 抽取失败时用户知道下一步做什么。

## 4. 边界与禁止

- 不追求完整功能；spike 代码可丢弃。
- 不提前优化性能；先证明可行，再谈优化。
- 不引入未登记依赖；不为 spike 改生产结构。
- 不用"我觉得"下结论；每个结论附实测数据。

## 5. 交付格式

按 findings 模板；额外附 5 份 spike 记录、对比表、ADR 更新建议。
