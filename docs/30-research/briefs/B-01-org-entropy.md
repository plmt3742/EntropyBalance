# 关于组织熵（协作混乱度）应如何定义、估算与验证

- 编号：B-01（对应 R-15）
- 优先级：P0
- 预计：6 人日
- 建议角色：分析/算法
- 决策用途：决定产品是否提供一个"混乱度/熵"总分；若提供，公式、因素、权重、展示方式全部由此单结论决定。
- 前置：无。可与 B-09 并行，但结论要合并。

## 1. 要回答的问题

1. "组织熵"在组织科学、管理学、网络科学里已有的定义有哪些？哪些有可操作公式，哪些只是隐喻？
2. 香农熵、网络熵、结构熵、Gini、HHI、Freeman 集中度、度分布熵，各自衡量什么？在 n=5–15、文本稀疏、观测不完整时，哪些还能算、哪些会失真？
3. "混乱度"应由哪些**可观测**因素构成？候选：责任分散、依赖集中、角色重叠、未完成事项堆积、决策无记录、沟通回路过长、任务状态反复、关键任务无备份。
4. 单一综合分是否必要？综合分会掩盖问题、诱导误用；分项指标 + 解释是否更合适？如果要做综合分，权重如何得到（等权/专家/数据驱动）？
5. 熵值随时间的变化能否作为"结构恶化"的早期信号？需要多长的时间窗、多少条记录才敢比较两个时点？
6. 如何验证这个分数？与负责人盲评、与断档事件、与团队自评（如愿意提供）对照，哪种可行？
7. 如何区分"健康的高熵"（多样性、冗余）与"病态的高熵"（混乱、断点）？

## 2. 调研需求

### 2.1 必须查的资料

- 组织熵 / organizational entropy / entropy in organizations / structural entropy / network entropy 的论文与综述（Google Scholar、CNKI、Web of Science）。
- Shannon (1948) 信息熵；Freeman (1979) 集中度；Burt (1992) 结构洞；Dunn (2010) 小网络指标敏感性。
- ONA 产品如何呈现"协作健康度"：Microsoft Viva Insights、Worklytics、Humanyze、Polinode 的指标说明（只看官方文档）。

### 2.2 必须做的动作

1. 做一张"术语审计表"：每个候选定义 → 是否有公式 → 需要什么数据 → 在 n=10 时是否可算 → 是否会被误读。
2. 选 2–3 种口径，在 1 个真实/合成组织上各算一遍，比较排名差异。
3. 给 3 位小组织负责人看 2 种展示（单一总分 vs 分项 + 解释），做 15 分钟概念测试：他们是否理解、是否知道下一步做什么、会不会拿它评价个人。
4. 做一次"反例测试"：构造一个熵高但结构健康的例子（如多人备份、任务多样），确认指标不会误报。

### 2.3 产出物

- `docs/30-research/findings/B-01-org-entropy.md`（按统一模板）。
- 指标定义表：因素、公式、数据来源、权重、适用范围、失效条件。
- 一页"该不该用熵这个词"的结论（允许结论是"不用"）。
- 概念测试记录（3 人，匿名）。

### 2.4 验收标准

- 能明确回答：用什么公式、由哪些因素、权重怎么来、什么时候不能算。
- 至少给出 1 个"高熵但健康"的反例，并说明指标如何避免误报。
- 3 位负责人中至少 2 位能在一分钟内说出"这个分数为什么高"。
- 若结论是"不做综合分"，也要给出分项清单与展示顺序。

## 3. 交互需求

### 3.1 用户要完成的动作

- 选择时间窗（近 30/90 天/自定义）。
- 查看混乱度总分（若采纳）与分项贡献。
- 点击任一分项，下钻到具体位置、连接或任务。
- （高级）调整权重或切换口径，看到排名变化，并能恢复默认。

### 3.2 界面必须表达的信息

- 总分 + 分项贡献 + 样本量（多少条记录、多少条断言、覆盖率）。
- 不确定性：区间或"结论不稳"提示，不能只给一个精确数字。
- 一句话定性："这是相对指标，用于发现位置，不用于评价个人。"
- 每个分数的来源：哪些任务/连接贡献最多，点得开、看得到证据。

### 3.3 必须支持的交互

- 空态/数据不足：明确说"需要至少 N 条记录"，不显示 0 分冒充低风险。
- 口径不可比：切换口径时提示"分数不可直接比较"。
- 下钻与返回：从总分 → 分项 → 实体 → 证据，路径可回退。
- 解释：每个分项有"为什么高"的人话解释，不用术语堆砌。

### 3.4 交互验收点

- 非专家 1 分钟内能说出"为什么高"和"先看哪里"。
- 不会把分数当成个人绩效（概念测试中明确询问）。
- 数据不足时不会给出误导性的低分。

## 4. 边界与禁止

- 不发明"组织熵"的专有定义并声称首创；只做组合与适配，引用来源。
- 不把熵值用于个人排名、绩效、离职预测。
- 不引入无法从记录观测的因素（心理安全感、信任度）作为默认权重；若要引入，必须单独标注为"用户输入"。
- 不在样本量不足时输出可比较的分数。

## 5. 交付格式

按 `docs/30-research/findings/README.md` 模板交付；额外附一张指标定义表和一张概念测试记录。
