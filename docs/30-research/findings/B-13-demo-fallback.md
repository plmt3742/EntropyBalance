## 1. 结论（≤5 行）

1. 现场失败的主因不是功能，而是环境：断网、投影分辨率、机器性能、端口占用。功能 bug 通常能在排练中暴露，环境问题只在现场出现。
2. 降级不是隐藏错误，而是**换载体**：在线 → 缓存结果 → 本地回放 → 静态页 → 录屏。每换一级，界面都要保留「这是演示数据」的标识。
3. 回放可信的前提是能证明它与在线一致：同一数据集哈希、指标在容差内、证据逐条相同。三者缺一，回放就会被当成「专门做的假数据」。
4. 9 分 30 秒的脚本按六段走：问题 → 导入 → 结构 → 风险 → 交接 → 边界。每段配一个备用动作，失败时跳段而不是停顿。
5. 三项演练（断网、低配、冷启动）与录屏未执行，因为没有可运行的演示版本；校验器与判据已就绪，拿到实例即可补测。

## 2. 失败模式与降级矩阵

### 2.1 排序依据

现场没有统计数据，因此不编造概率。排序按两个维度估计：**发生可能性**（场地条件决定）与**后果严重度**（是否导致演示中断）。两者都高的排前面。

| # | 失败模式 | 可能性 | 后果 | 检测方式 | 降级动作 | 用户可见提示 |
|---|---|---|---|---|---|---|
| 1 | 场馆网络不可用或受限 | 高 | 高 | 启动时探测一次，之后每 10 秒心跳 | 切本地回放 | 当前为本地演示数据 |
| 2 | 模型接口超时或限流 | 中高 | 高 | 单次请求 8 秒超时 | 用预计算结果替换该步 | 结果来自本地缓存 |
| 3 | 投影分辨率或缩放导致布局崩 | 高 | 中 | 启动时读取窗口尺寸 | 切紧凑布局（固定 1280×720） | 已切换演示布局 |
| 4 | 机器性能不足、渲染卡顿 | 中 | 高 | 首屏渲染超过 3 秒 | 切静态图与人眼可读的降采样 | 已切换轻量视图 |
| 5 | 端口占用、服务起不来 | 中 | 中 | 启动脚本探测端口 | 换端口并打印可用地址 | 无（启动阶段处理） |
| 6 | 依赖缺失、Node/Python 版本不符 | 中 | 高 | 启动自检 | 用打包好的离线包，不现场装依赖 | 无（启动阶段处理） |
| 7 | 数据文件缺失或损坏 | 中 | 中 | 启动时校验数据集哈希 | 切备用数据集 | 已切换备用数据集 |
| 8 | 浏览器版本或缓存差异 | 中 | 中 | 启动时读版本号 | 用随包携带的浏览器 | 无（启动阶段处理） |
| 9 | 字体缺失导致中文显示为方块 | 中 | 中 | 启动时测量一个汉字宽度 | 切随包字体 | 无（自动加载） |
| 10 | 输入法、系统通知、自动更新弹窗 | 中 | 高 | 无法自动检测 | 检查清单里手动关闭 | 无 |

前八项按任务单要求设计降级；第 9、10 项来自排练经验，成本低，一并列入。

### 2.2 降级阶梯

五级，越往下依赖越少、可信度越低，但都能把话讲完。

| 级别 | 载体 | 依赖 | 可用能力 | 失去 |
|---|---|---|---|---|
| L0 在线 | 现场网络 + 模型接口 | 网络、密钥、配额 | 全部，含即时重算 | — |
| L1 缓存结果 | 本地预计算结果 + 在线界面 | 仅浏览器 | 全部展示，不能重算 | 现场改参数后的结果 |
| L2 本地回放 | 离线包（本地服务 + 数据） | 本机 | 展示、切数据集、翻步骤 | 模型调用 |
| L3 静态页 | 截图 + PDF 清单 | 文件查看器 | 按图讲解 | 交互 |
| L4 录屏 | 提前录好的视频 | 播放器 | 按视频讲解 | 一切交互 |

切换规则：

- **自动**只发生在 L0 → L1/L2，且必须由检测触发，不由人工「感觉不对」触发。
- **手动**入口始终存在：右上角状态徽标可点，一键切换任意级别。
- 每级切换成本控制在一次点击；L3、L4 由键盘快捷键触发，避免现场翻文件夹。
- 从 L2 回到 L0 不做自动恢复，避免网络抖动造成来回跳变。

### 2.3 状态机

四个状态、五个事件，转移表必须穷举，否则现场会出现「既显示在线又显示回放」的矛盾。

| 当前 | 事件 | 下一状态 | 动作 |
|---|---|---|---|
| 在线 | 心跳失败 | 回放（降级） | 加载离线包，徽标变黄，提示「本地演示数据」 |
| 在线 | 单次请求超时 | 缓存结果（降级） | 仅该步替换为预计算结果，徽标变黄 |
| 缓存结果 | 心跳恢复 | 缓存结果 | 不自动回在线，等用户点击 |
| 回放 | 用户点击「恢复在线」 | 在线 | 重新探测，失败则留在回放 |
| 任意 | 用户按 `F12` 之外的切换键 | 静态页 | 打开随包的静态页，徽标变灰 |

状态徽标三色：在线为蓝、降级为黄、静态或录屏为灰。颜色之外必须带文字，避免色觉差异与投影偏色。

## 3. 回放包

### 3.1 要保存什么

| 内容 | 是否预计算 | 理由 |
|---|---|---|
| 原始记录 | 是（随包） | 现场不能依赖外部数据源 |
| 断言与证据偏移 | 是 | 抽取结果不稳定，回放必须固定 |
| 图布局坐标 | 是 | 力导向布局每次不同，现场重算会「跳图」 |
| 指标 | 是 | 与在线结果比对，必须同源 |
| 建议文本 | 是 | 生成式内容不可复现 |
| 交接清单 | 是 | 同上，且是演示终点 |
| 筛选、排序、展开状态 | 否 | 前端即时计算，成本低且必须可交互 |

判断标准：**凡是模型产出或带随机性的，都预计算；凡是用户操作产生的，都实时算。**

### 3.2 包结构

```text
demo-team-a-pack/
  manifest.json          数据集哈希、工具版本、生成时间、指标
  records.jsonl          脱敏记录
  assertions.jsonl       断言与证据偏移
  graph.json             节点、边、布局坐标
  metrics.json           指标快照
  suggestions.md         建议文本
  handover.json          交接清单
  static/                截图与清单 PDF（L3 用）
  playback.mp4           录屏（L4 用）
```

`manifest.json` 是唯一入口：启动时先校验它，哈希不符直接切备用数据集，不进入演示流程。

### 3.3 一致性校验

校验器为本地脚本，离线可用，不需要产品运行。

判据三条：

1. **数据集哈希相同**。不同就是换了数据，直接判失败，不进入指标比较。
2. **指标在容差内**。整数必须完全相等；浮点相对容差 1e-6。计数类（节点、边、清单条数）不接受任何漂移。
3. **证据逐条相同**。比对前统一空白与全角空格；顺序不同也算不一致，因为证据顺序对应清单顺序。

输出为 JSON，含差异类型、指标名、两端取值。退出码 0 一致、1 有差异，可直接接进启动脚本。

示例：

```bash
python b13_check_replay.py 在线结果.json 回放结果.json
```

## 4. 演示脚本（9 分 30 秒）

总时长按 9:30 设计，留 30 秒余量应对设备切换。每段都写「备用动作」，失败时跳段而不停顿。

| 时间 | 段落 | 讲解要点 | 备用动作 |
|---|---|---|---|
| 0:00–0:40 | 开场 | 一句话说清问题：小型组织的协作结构看不见，人一走就断 | 无（不用电脑） |
| 0:40–1:40 | 导入 | 展示输入只有会议记录，不做问卷、不装软件 | 切 L2 回放，直接放导入完成的界面 |
| 1:40–3:30 | 结构 | 图上指出过度集中、单点承担、职责重叠三处 | 用静态图讲解，跳过交互 |
| 3:30–5:00 | 风险 | 指出依赖割点与无备份位置，说明凭什么是这几处 | 切 L1，用缓存指标 |
| 5:00–7:00 | 交接 | 移除数据，看断档扩散，再生成三组清单 | 切 L2，播放预置的移除动画 |
| 7:00–8:30 | 清单 | 逐条讲「必须补位」的三条与推荐依据 | 打开 PDF 清单（L3） |
| 8:30–9:30 | 边界 | 明确不做什么：不预测离职、不评价个人、不做裁员清单 | 无（可脱稿） |

时间分配的理由：结构与交接各占约 1/4，是产品的差异点；开场与边界各 40–60 秒，用于建立信任；导入只占 1 分钟，避免把时间花在「传文件」上。

## 5. 现场检查清单（打印版）

### T-1 天

- [ ] 离线包可在断网机器上启动，且校验通过
- [ ] 录屏文件可播放（不是「有文件」）
- [ ] PDF 清单与截图已导出，字体嵌入
- [ ] 备用机器完成一次冷启动
- [ ] 电源、HDMI 转接头、扩展坞齐备
- [ ] 浏览器版本与随包浏览器一致

### T-30 分钟

- [ ] 开机并启动服务，记录启动耗时
- [ ] 投影已连接，分辨率与缩放已确认
- [ ] 界面在投影上无裁切，最小字号可读
- [ ] 系统通知、自动更新、输入法候选框已关闭
- [ ] 网络：确认可用；若不可用，直接进 L2
- [ ] 音量与录屏音量已测试

### T-5 分钟

- [ ] 回到演示起点，数据与指标为初始状态
- [ ] 状态徽标显示「在线」或明确的降级级别
- [ ] 标记「本机为演示机」，避免他人误操作
- [ ] 快捷键卡片放在手边

## 6. 界面表达

| 元素 | 位置 | 要求 |
|---|---|---|
| 状态徽标 | 右上角常驻 | 三色 + 文字：在线 / 降级 / 回放 / 静态 |
| 数据集名 | 徽标左侧 | 显示名称与时间范围，便于评委核对 |
| 降级原因 | 徽标悬浮或点击 | 一句话，不含堆栈与错误码 |
| 下一步提示 | 左下角 | 可关闭；演练时用于提醒操作者 |
| 快捷键 | 帮助浮层 | `→` 下一步、`←` 上一步、`R` 重置、`F` 切换回放 |

禁止出现的表达：`Error`、`500`、`timeout`、堆栈、`请检查网络`。降级后只保留一句「当前为本地演示数据」，其余技术细节写进日志。

## 7. 边界

- 不隐藏「这是回放」，不把预计算说成实时计算。
- 不用真实组织数据做公网或公开演示。
- 不依赖现场网络与第三方模型；不假设有 IT 支持。
- 不为演示效果修改指标或伪造证据。回放与在线的差异必须能解释，不能靠调参抹平。

## 9. 下一步

1. 演示版本可用后，按第 8 节顺序补测：先冷启动，再断网，最后低配。冷启动不过关时，后面两项没有意义。
2. 用 `b13_check_replay.py` 把「回放与在线一致」变成每次发版的固定检查，而不是答辩前的一次性动作。
3. 录屏按第 4 节脚本录，保留降级片段；录屏里出现降级，比只录顺利路径更可信。
4. 检查清单打印后实际走一遍，删掉现场用不到的项；清单越长，越容易被跳过。
5. 答辩前一周做一次全流程计时，按 9:30 卡表；超时就砍第 3 节的图交互，不砍交接段。
