# 项目章程

- 项目名：EntropyBalance（暂定中文名：熵衡）
- 版本：v0.1（2026-11-17）
- 状态：设计阶段，未开始编码
- 参赛：2027 年（第 20 届）中国大学生计算机设计大赛

## 1. 问题

十人上下的小型组织依靠熟悉关系与口头约定运转。人员更替或任务量增长时，问题集中出现：同一件事反复沟通、责任边界模糊、关键环节长期由一人承担，该成员退出即断档。

成员的能力与投入并未变化，变化的是**成员之间承担协作的连接**。因此问题在结构，不在个体。

现有工具（任务管理、即时通讯、在线文档）回答"发生了什么"，不回答：

- 现有协作结构是否还能承载当前任务？
- 哪个位置只剩一人在承担？
- 谁离开后，哪些连接会断？

这些判断目前依赖负责人经验，不可传递、不可复用。

## 2. 目标用户

| 维度 | 画像 |
|---|---|
| 规模 | 5–15 人 |
| 管理 | 无专职管理岗，负责人兼业务 |
| 记录 | 有群聊/会议纪要，但格式随意、不连续 |
| 痛点 | 交接靠嘴、断档靠救火、责任靠记忆 |
| 典型 | 学生团队、工作室、小微创业团队、社团、公益小组 |

明确不服务：需要流程引擎与审计合规的中大型组织。

## 3. 目标

1. **可观察**：从既有记录中抽取决定、待办、责任人、依赖，还原真实协作关系，指认依赖集中、单点承担、职责重叠等具体位置。
2. **可依据**：给出调整建议，说明预期效果、影响范围与实施代价；人员更替时生成交接清单，指明需补位的连接与中断风险。
3. **可复用**：沉淀稳定的抽取口径、判断逻辑与调整流程，使工具能适配不同小型组织持续运行。

## 4. 非目标

- 不做通用即时通讯或任务管理系统的替代品。
- 不做员工绩效评估、考勤监控、离职预测、心理测评。
- 不自动执行调整；所有变更由人确认后生效。
- 不追求覆盖大型组织的流程、权限与合规体系。
- 不在本期训练自有基座模型。

## 5. 核心概念

| 概念 | 一句话 |
|---|---|
| 连接 | 两人因共同承担具体事项形成的协作关系 |
| 位置 | 组织持续需要的一组职责，与人分离，可被不同人占据 |
| 承载 | 某位置/连接当前承担的任务量与关键程度 |
| 单点承担 | 某位置只有一人能承担且无备份 |
| 断档 | 人员退出或缺位后，事务无人接续 |
| 证据 | 支撑每条结论的原文片段，必须可回看 |

完整定义见 `.agent/30-architecture/domain-glossary.md`。

## 6. 成功标准（目标值，待真实数据标定）

| 编号 | 指标 | 目标 | 验证方式 |
|---|---|---|---|
| S1 | 抽取字段 F1（决定/待办/责任人/依赖） | ≥0.75 / 0.75 / 0.80 / 0.65 | 自建中文标注集，双人标注 + 一致性检验 |
| S2 | 结构风险 Top-5 与负责人人工诊断的一致率 | ≥60% | 2 个以上真实组织盲评 |
| S3 | 交接清单覆盖率 | 关联任务 100% 覆盖，"必须补位"项无遗漏 | 3 个模拟离职场景 + 负责人复核 |
| S4 | 演示闭环 | 3 分钟内完成 导入→图谱→风险→建议→交接 | 离线环境实测 3 次，2 次成功即算通过 |
| S5 | 真实使用 | 2 个小组织连续使用 2 周，≥1 个愿意继续 | 使用记录 + 简短访谈 |

S1 的数值是当前设定，不是实测结果；第一次评测后必须回填真实值并调整。

## 7. 约束

| 类型 | 约束 |
|---|---|
| 参赛 | 本科生 2–5 人，指导教师 ≤2；国赛现场答辩 ≥2 人；陈述+演示 ≤10 分钟 |
| 时间 | 2026-11 至 2027-08；2027 规则预计 2027-03 发布 |
| 人力 | 4 人，均为学生，无专职管理；开发方式为 vibecoding（AI 辅助，队长统筹） |
| 数据 | 只能使用获得同意的组织记录；原始数据不出本机、不入库 |
| 技术 | 现场网络不可依赖；第三方模型不可假设可用 |
| 合规 | 遵守《个人信息保护法》基本要求：告知、同意、最小必要、可删除 |
