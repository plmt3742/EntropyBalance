# 协作与开发流程

- 版本：v0.1（2026-11-17）
- 前提：4 人、vibecoding、队长统筹、比赛期约 8 个月
- 目标：让"人 + AI"同时工作时，冲突少、返工少、上下文不丢

## 1. 决策权

| 事项 | 谁定 | 记录在哪 |
|---|---|---|
| 选题、赛道、范围 | 队长 | ADR |
| 目录结构、依赖、数据模型 | 队长 | ADR |
| 模块内部实现 | 模块 owner | 模块页 + 提交信息 |
| 接口契约 | 后端 owner 提，前端确认 | `packages/shared/` |
| 文案与演示脚本 | 队长定稿 | `docs/` |

有异议先说，不执行"先做了再吵"。队长拍板后执行；事后认为错了，写 ADR 推翻，不私下改。

## 2. 分支与提交

- `main` 始终可运行；不允许把跑不起来的代码合进去。
- 功能分支：`feat/<scope>-<slug>`，如 `feat/extract-assertion-schema`。
- 修复分支：`fix/<scope>-<slug>`。
- 文档与小改可由队长直接提交 `main`；代码改动走分支 + 合并前自检。
- 提交信息：`<type>(<scope>): <subject>`，英文，一次提交一件事。
- 不提交生成物、数据库、`data/raw/`、`.env`；`git status` 不干净不合入。

## 3. 任务粒度（vibecoding 的关键）

- 一个任务 = 一个可独立验收的产出（一个模块、一个页面、一个脚本）。
- 一个 agent 会话只做一个任务；任务写在 `.agent/80-tasks/current.md`。
- 任务描述必须包含：目标、输入、输出、验收标准、禁止事项。
- 超过 3 个文件的改动，先拆；拆不动说明设计没想清楚，先写 ADR。

## 4. 给 AI 的上下文纪律

1. 从 `.agent/BOOT.md` 开始，按 `INDEX.md` 路由，只喂相关文件。
2. 不把 `data/raw/`、真实聊天原文、`.env` 贴进任何对话或工具。
3. 要求 agent 先复述任务与验收标准，再动手；跑偏立即停。
4. 要求给出改动文件清单与验证结果；"应该可以"不算完成。
5. 结构性改动后，让 agent 跑 `gen-file-tree.mjs` 与 `check-context.mjs`。
6. 会话结束按交接模板留档，避免下一个会话重新摸索。

## 5. 交接模板

```text
任务：
已完成：
未完成 / 卡点：
改动的文件：
验证方式与结果：
下一步：
需要谁决定：
```

## 6. 合并前自检

- [ ] 行为符合验收标准，有可复现的验证步骤
- [ ] 新增/修改的逻辑有测试；测试能失败也能通过
- [ ] 没有真实姓名、原文、密钥、数据库文件
- [ ] 没有 `any` / `# type: ignore` / 空 catch
- [ ] 目录职责未被破坏；新文件已登记 `FILES.md`
- [ ] 影响口径的改动已更新文档或 ADR

## 7. 节奏

| 时间 | 动作 | 产出 |
|---|---|---|
| 周一 | 定本周 3 条线，写进 backlog | 本周目标 |
| 周三 | 中途检查：是否卡在同一处超过半天 | 调整或求助 |
| 周五 | 演示当前进度 + 更新 CHANGELOG | 可运行增量 |
| 每月末 | 回看 ADR 与风险表 | 决策复核 |

## 8. 比赛期冻结

- 省赛提交前 2 周：只修 bug，不调提示词、不改指标、不换依赖。
- 国赛前 3 周：只做稳定性、演示脚本、答辩材料。
- 冻结期的例外必须队长书面同意，并记录在 CHANGELOG。
