# 4C 2027 参赛解读（基线：2026 年第 19 届）

- 版本：v0.1（2026-11-17）
- 官方来源：<https://jsjds.blcu.edu.cn/>
- **重要前提**：截至 2026-11-17，2027 年（第 20 届）通知尚未发布。以下规则取自 2026 年（第 19 届），2027 可能调整，发布后必须逐条复核（清单见 `.agent/70-competition/rules-watch.md`）。

## 1. 赛事基本盘（2026 年事实）

| 项 | 内容 |
|---|---|
| 全称 | 中国大学生计算机设计大赛（4C），2008 年创办 |
| 层级 | 校级赛 → 省级赛 → 国赛；国赛只接受省级赛上推作品 |
| 对象 | 全国普通高校当年在籍本科生（含港澳台、来华留学生） |
| 组队 | 同一院校 2–5 名本科生；指导教师 ≤2 名；每位作者每大类限 1 件 |
| 答辩 | 线下；到场作者 ≥2 人；陈述+演示 ≤10 分钟 |
| 奖项 | 一等 ≤5%，二等 ≥25%，三等 70% |
| 名额 | 每校每大类入围国赛 ≤3 件，每小类 ≤2 件（2025 规程口径） |
| 大类 | 11 类：软件应用与开发、微课与AI辅助教学、物联网、大数据、人工智能应用、信息可视化、数媒静态、数媒动漫、数媒游戏、计算机音乐、国际生汉学 |
| 决赛区 | 上海、杭州、合肥、长春、青岛、无锡（2026 年 7–8 月） |

## 2. 与本项目直接相关的两类

### 2.1 人工智能应用（主选）

- 小类：人工智能实践赛、人工智能挑战赛。
- 实践赛要求：针对某一领域特定问题，提出基于人工智能的解决方案；需完整方案设计 + 代码实现 + 文档 + 源码 + 用户手册 + 功能演示视频；**现场必须演示系统功能**。
- 适合点：本项目是"自然语言处理 + 组织协作分析"的完整应用，属于实践赛描述的范围。
- 风险点：评委可能追问模型层面的贡献。仅调用第三方 API 会被压分。

### 2.2 软件应用与开发（备选）

- 小类：Web 应用与开发、管理信息系统、移动应用（非游戏）、算法设计与应用、企业专项赛。
- Web 类要求：提供可在互联网访问的地址（如有）；提交完整源代码与技术文档。
- 适合点：系统形态完整，工程实现可讲。
- 风险点：容易被归为"任务管理系统"，核心贡献被界面掩盖。

### 2.3 结论

主报**人工智能应用/实践赛**，备选**软件应用与开发/Web**。两套材料共用一套系统，差别在文档重心与演示侧重。模型统一用 DeepSeek（在 2026 年指定国产工具清单内），使赛道切换不触发合规风险。

## 3. 硬性合规要求

| 要求 | 我们的做法 |
|---|---|
| 原创、未重复参赛、无一稿多投 | 2026-11 起全新开发；不投其他赛事 |
| 完成时间窗（2026 年为 2025-07-01 至 2026-06-30，校方转述） | 开发起点 2026-11，处于下一届窗口内；以 2027 原文为准 |
| AI 工具限制（2026 年：使用 AI 工具须为指定 15 款国产工具或自主知识产权工具；条款文字覆盖"参赛作品"，适用范围以原文为准） | 全程使用 DeepSeek（在 2026 指定清单内），不依赖清单外工具 |
| 源码与文档齐备 | 从第一天起保留提交历史与文档，不做事后补材料 |
| 数据与地图合规 | 不涉及地图；数据来自知情同意的组织记录，脱敏后使用 |
| 学术诚信 | 引用公开数据集、论文、开源库，逐一标注来源与许可证 |

## 4. 评审维度（归纳，非官方权重）

> 官方评分表未获取。以下维度据 2026 规程表述与往届获奖作品特征归纳，仅用于自查；2027 规程发布后以其原文为准。

| 维度 | 我们靠什么拿分 | 当前短板 |
|---|---|---|
| 选题价值 | 小型组织断档是真实、普遍、少被工具化的痛点 | 缺外部组织的一手证据 |
| 技术方案 | 抽取 schema + 评测 + 图算法 + 变更仿真，四层可分别讲清 | 尚无代码与实验数据 |
| 创新性 | "把建议表示成图上的可执行编辑并重算效果" | 需与既有 ONA 工具划清边界 |
| 完成度 | 端到端闭环 + 离线可演示 | 从零开始，时间紧 |
| 文档 | 结构、口径、指标一致，可复算 | 等 2027 模板 |
| 现场表现 | "成员退出→断档可视化"的强叙事 | 需反复演练 |
