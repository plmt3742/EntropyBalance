# B-08 依赖标注规范（v0）

用于 `v0/sentences.jsonl`。改动规范时新建版本目录，不覆盖本文件。

## 1. 字段定义

| 字段 | 含义 | 取值 |
|---|---|---|
| `id` | 句子编号 | `S001`–`S100` |
| `rec` | 来源记录 | `records.jsonl` 中的 `id` |
| `text` | 原句 | 从记录中切出的句子，不改写 |
| `dep` | 是否为依赖 | `1` / `0` |
| `type` | 类别 | 依赖：前置 / 资源 / 审批 / 信息 / 同步；非依赖：承诺 / 无 |
| `dir` | 方向 | 依赖：`依赖方<-被依赖方`；承诺：`承诺人->事项` |
| `str` | 强度 | 依赖：硬 / 弱；非依赖：无 |
| `ev` | 证据 | 必须是 `text` 的精确子串 |
| `note` | 备注 | 判定理由，尤其是反例的理由 |

## 2. 判定顺序

对每一句依次问三个问题，任一为否即停：

1. 句子里有没有两个可识别的动作或状态？（只有一个，判 0）
2. 其中一个是另一个的前提吗？（不是前提，判 0）
3. 能指出谁等谁吗？（指不出，判 0；不要靠猜补全）

三个都为是，才记 `dep=1`。

## 3. 硬与弱的边界

判断标准是后果，不是语气。

- 缺了它，任务交不了：硬。
- 缺了它，任务能交，只是变差、变慢或需要绕路：弱。
- 例：「等 P04 定稿再动」→ 硬，因为尺寸对不上就做不了。
- 例：「最后一页数据先空着」→ 弱，因为可以先交，事后再补。

## 4. 边界案例

| 案例 | 判定 | 理由 |
|---|---|---|
| 「P03 说文档还没整理」 | 0 | 状态陈述，没有第二个动作 |
| 「演示时先避开那个页面」 | 依赖，弱 | 演示可推进，但要绕开未修的 bug |
| 「建议从这些批次中选取」 | 依赖，弱 | 选择依赖批次信息，但不选也能办 |
| 「6E 与 6D 有连通通道，搬运方便」 | 依赖，弱 | 影响选址的软约束 |
| 「辛苦了」 | 0 | 礼貌语 |
| 「如果评委问，他来讲」 | 0（承诺，弱） | 条件不成立时不生效 |
| 「老师说要交一版」 | 0 | 转述他人要求 |
| 「我来吧」 | 0（承诺，硬） | 承诺不构成对他人的依赖 |

## 5. 分歧裁决

- 两人独立标注，分歧不强行统一，各自写明理由。
- 方向分歧优先核对「谁停下来了」。停下来的那一方是依赖方。
- 强弱分歧优先按「能否交付」判断；仍不一致时记为弱，并在 `note` 注明。
- 同一句含多条边时，只标最主要的一条，其余在 `note` 列出，留待 v1 拆分。

## 6. 本版已知缺陷

1. 69 条正样本，未达「100 条含线索」的要求，原因是语料总句数有限。
2. 无玩笑类反例。
3. 同一句多边未拆分，只取主边。
